# Documenti di dominio

Contesto unico: leggere `GLOSSARY.md` e gli ADR pertinenti in `docs/adr/` prima di progettare o implementare. Gli ADR con stato `proposed` registrano opzioni, non decisioni approvate.

Usare i termini del glossario per requisiti, UI, ticket e modelli. Per aggiungere o cambiare un termine applicare `domain-modeling`. Tenere implementazione e API nella spec o nei documenti di architettura, non nel glossario.

Segnalare un conflitto con un ADR e proporre l'aggiornamento motivato. Non trattare una raccomandazione preliminare come vincolo irrevocabile.
