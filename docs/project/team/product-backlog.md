## Reading the status labels

- Accepted/current: user-approved product requirement, not proof of implementation. Historical/superseded/future decisions are called out explicitly.
- Implemented slice: code exists for the named increment. It does not imply all requirements in that feature card are implemented.
- Tested: supported by a named automated test/gate. Static test coverage is not live/backend acceptance.
- Live unverified: no claim of live Hermes runtime, real provider, macOS, accessibility or release acceptance unless explicitly stated.
- Priority: release value and prerequisites, not permission to break ADR0006 (one selected feature/increment per implementation chat).
